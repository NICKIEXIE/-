# 代运营接单：把短视频做成生意

只负责把短视频做成可交付、可收款、可验收、不出事的生意；内容怎么做归其它 skill，本 skill 一句话指向即可。

> **来源声明（全篇适用）**
> 本 skill 所依据的《薛辉手册》“视角二”整体是【本手册推断·落地建议】，**不是官方 SOP，也不是薛辉原话**。
> 手册附录 C.3 已逐条列出：客户问题清单、诊断表、交付物清单、报价模型、合同风险清单、验收标准、话术，全部标注为“▸ 落地建议（非官方SOP）”。
> 引用时一律保留此说明，禁止说成“薛辉要求”“官方标准流程”，也禁止给推断内容加引用式口吻。

## 定位

- **你负责**：客户沟通、诊断、报价、合同、交付、验收、产能与风险。
- **你不负责**：单条视频的脚本、拍摄、剪辑、投放操作与数据诊断方法本身。
- 遇到不属于本 skill 的问题，给**一句话结论 + 指向正确 skill**，不要展开：
  - 脚本/口播/分镜/剪辑/发布 → `shortvideo-production`
  - DOU+ 投放、数据指标、AB Test、直播 → `shortvideo-growth`
  - 定位、赛道、账号搭建、起号排期 → `shortvideo-launch`
  - 岗位分工、SOP、拆片会、审片、绩效 → `shortvideo-team`
- 对客户要能讲明白内容逻辑（手册建议代运营从业者第 1–14 章通读），但不要把这本 skill 当成内容制作工具来用。
- 本 skill 的产出始终是**商业文件**：诊断表、方案、报价、合同附件、验收单。判断口径永远落到“能不能交付、能不能验收、会不会出事”。

## 红线：不可兑现的承诺（V2-2.1，最重要的一节）

**这一节优先于本 skill 的其它一切内容。** 任何报价、方案、合同、聊天记录里出现“包做成”类表述，都算红线事故，必须当场改口。先立规矩，再谈单。

### 为什么“包把账号做起来”不可能兑现

手册用一条真实投诉做反面教材（黑猫投诉，涉及《0基础短视频实操变现训练营》，属【第三方转述·真实负面案例】）：投诉原文的核心不是课程质量，而是“包把账号做下来”这个承诺本身。四条理由缺一不可地讲给客户听：

| # | 原因 | 讲给客户的话 |
|---|---|---|
| ① | 结果不由单方面决定 | 账号起不起得来取决于产品竞争力、供应链、价格、交付能力、老板配合度、行业周期，这些都不在服务方控制范围内 |
| ② | 平台算法是变量 | 抖音的规则与流量结构持续变化，手册里的流量结构数据本身就是特定时点的 |
| ③ | “做起来”没有定义 | 涨粉 1 万算不算？有咨询没成交算不算？定义不清就必然扯皮 |
| ④ | 法律上是“效果承诺” | 一旦写进合同或留在聊天记录，客户可以据此要求退款甚至索赔 |

### ✅ 可以承诺的（过程性指标）

- 每周 / 每月交付 X 条成片
- 每月完成 X 场选题会、X 场复盘会
- 交付素材库、脚本、数据周报/月报等具体产物
- 按约定时间节点完成发布
- 提供承诺数量的优化迭代次数

### ❌ 不能承诺的（结果性指标）

- “包你把账号做起来”
- “保证涨粉 XX 万”
- “保证月销 XX 万”或“保证成交 XX 单”
- “保证上热门”
- “做不到全额退款”——这是最危险的表述

### “效果承诺”的正确表述（V2-2.6.1）

- ❌ 错误写法：“乙方负责将甲方抖音账号运营至粉丝 XX 万、月成交 XX 单。”
- ✅ 正确写法：“乙方负责按本合同约定完成内容制作与运营服务，交付物详见附件一。乙方不承诺账号粉丝量、播放量、成交量等结果性指标。双方同意以过程性指标的完成情况作为服务验收依据。”

### 延伸纪律

- 过程性指标只写**服务方直接交付**的东西：成片条数、会议场次、报告份数、发布时间。
- 曝光量、咨询量这类受算法与客户端承接影响的指标，可以写进“协同目标”，**不得写成保证**，也不得作为退款条件。
- 报价里的“效果激励”触发条件同样只能用可客观衡量的过程指标，**不要用成交额**——那是客户自己交付能力决定的。

## 第一步：诊断（R1 的提问清单）

分两层问，**一次问完，不要挤牙膏**。两层都直接复用 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的问题清单与诊断表结构，**不要另发明一套**。

**A 层：客户基本情况（账号策划输入项，9 问）**

| # | 问题 | 用途 |
|---|---|---|
| 1 | 您是谁？（姓名/称呼/身份） | 人设基础 |
| 2 | 您是哪里人？ | 地域标签（同城流量的关键） |
| 3 | 您的年龄？ | 人设与表达风格 |
| 4 | 您的性格？ | 决定出镜风格 |
| 5 | 您的行业是什么？做了多久？ | 内容方向 |
| 6 | 有什么荣誉/资质/证书？ | 背书素材（背景图、简介用） |
| 7 | 产品的客单价大约多少？ | 决定变现路径 |
| 8 | 有多少员工？ | 判断能配合的拍摄资源 |
| 9 | 您的商业目的是什么？（卖货/引流/招商/品牌） | 最关键的一问 |

**B 层：深度诊断问题（决定成功率，13 问）**

| # | 问题 | 为什么问 |
|---|---|---|
| 10 | 您现在有没有做过抖音？做多久了？ | 判断是冷启动还是有基础 |
| 11 | 之前做过的话，具体数据是多少？（粉丝/播放/成交） | 判断真实起点 |
| 12 | 您觉得之前做得不好，原因是什么？ | 了解客户的认知偏差 |
| 13 | 您的客户是谁？他们最常问您什么问题？ | 选题金矿 |
| 14 | 您成交的最典型的一单是怎么来的？ | 找到可复制的内容钩子 |
| 15 | 您最想让谁看到您的视频？ | 明确目标人群 |
| 16 | 您最不希望谁看到？ | 避免误伤（如 B 端业务不想被同行看到报价） |
| 17 | 您的产品/服务和同行最大的区别是什么？ | 差异化定位 |
| 18 | 您能配合出镜吗？每周能配合几次、每次多久？ | 这是最常见的失败原因 |
| 19 | 您能提供哪些素材？（产品、场地、案例） | 判断内容产能 |
| 20 | 您的预算范围和期望周期？ | 报价基础 |
| 21 | 您希望多久看到什么结果？ | 预期管理——必问 |
| 22 | 如果三个月没效果，您会怎么想？ | 提前暴露分歧 |

**筛客户的两个关键问**：第 18 问（配合度）与第 22 问（预期）。

- 客户说“我很忙，全交给你了” → 高危信号。没有老板配合的账号，几乎做不起来（真人 IP 尤其如此）。
- 客户期望“一个月爆” → 当场讲清楚，否则三个月后必然纠纷。
- 宁可前期丢掉这个单，也不要后期赔钱赔时间。公开素材提到代运营签约周期通常是三个月（【第三方转述】），这三个月的成本很高。

## 工作流

**路径约定**：以下每步的知识库路径完整写法为 `<skill-directory>/../knowledge/薛辉手册/NN-xxx.md`，例如 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md`。**引用时一律给完整路径**，不要把文件名单独丢给用户。

1. **接单前先立规矩。** 读 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.1 与 V2-2.6.1，把“不承诺结果”的话术放在客户开口之前说出来。产出：本人口径备忘（可承诺清单 / 不能承诺清单 / 一段标准回答）。
2. **第一次沟通，问完 22 问。** 用上面的 A/B 两层清单；可选项用 `ask_user_question`，信息多时用表格一次列全。产出：22 问回答记录。客户答不上来的项标“待补”，**不许用行业均值代替**。
3. **24 小时内出书面诊断表。** 照 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.3 结构，按其六段（客户档案 / 商业信息 / 内容基础 / 资源盘点 / 诊断结论 / 风险评估）填写。产出：模板① 客户需求诊断表，发客户确认。
4. **补商业定位判断。** 读 `<skill-directory>/../knowledge/薛辉手册/07-第2章-商业定位-先想清楚靠什么赚钱.md`，判商业目的与变现方式是否成立、能否标准化；读 `<skill-directory>/../knowledge/薛辉手册/19-第14章-变现体系-心理账户与价值链.md`，判价值链上“客户接不住流量”的环节在哪（主页图、商品评分、详情页、购物车图片、跳转链路）。产出：诊断结论里的商业定位建议 + 变现路径建议（套用手册方法论，并说明是套用）。
5. **出服务方案与交付物清单。** 复用 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.4 清单：启动期（定位方案、账号搭建、对标账号分析表、内容规划）、运营期（成片、选题库、脚本、数据周报、数据月报）、复盘期（月度复盘会、优化方案）。读 `<skill-directory>/../knowledge/薛辉手册/09-第4章-账号搭建-四要素与对标三维度.md` 确认启动期交付物口径。产出：模板②。
6. **报价。** 按成本法（人力人天 × 市场日薪 × 1.5–3 倍）、价值法（客户一单值多少、几单覆盖服务费）、市场法（同城同行业区间）三个参照系定价，再从基础档/标准档/高阶档/顾问档里选一档。读 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.5——该报价模型标注为【本手册推断】，**不是薛辉体系的定价标准**；手册里 4980/5980/7980 元是薛辉自身课程产品价格，**与代运营服务报价无关**（见附录 A）。产出：模板③。
7. **签约前逐条核对合同风险。** 用 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.6 十二项：效果承诺、服务范围、内容条数、修改次数、客户配合义务、账号归属、素材版权、付款节奏、保密与竞业、终止条款、不可抗力与平台规则变化、目标定义。逐条落进合同或附件。产出：模板④ + 合同修改意见。
8. **开工前确认客户配合义务。** 把出镜人、每周配合时长、素材提供清单、审批响应时限写成附件；未履行则工期顺延。读 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.2 第 18 问与 V2-2.6 第 5 项。产出：配合义务确认单。
9. **交付留痕。** 每一项交付物通过邮件/企微/飞书发送并留记录，建共享文件夹按月归档，每周固定时间发一次交付确认。原因：代运营纠纷中最大的争议是“你到底做了什么”，有记录才能证明工作量。产出：交付台账。
10. **按周/月/季度验收。** 用 `<skill-directory>/../knowledge/薛辉手册/22-视角二-代运营接单.md` 的 V2-2.7 四类验收：交付物验收（有/无，每周）、数量验收（数字比对，每月）、质量验收（按脚本比对，每月）、阶段评审（看数据趋势不看绝对值，每季度）。产出：模板⑤ 验收单。
11. **数据与投放口径对齐。** 需要算收入、利润、ROI 或咨询量时，读 `<skill-directory>/../knowledge/薛辉手册/30-附录F-全流程速查表-可打印.md` 的 F.3 关键公式；涉及投放方案与指标口径时读 `<skill-directory>/../knowledge/薛辉手册/16-第11章-DOU-投放-把钱花在刀刃上.md` 与 `<skill-directory>/../knowledge/薛辉手册/17-第12章-数据分析-看什么指标-算哪几个公式.md`。产出：写进月报的口径说明（投放类结论交给 `shortvideo-growth` 深化，不要在这里自创指标）。
12. **验收争议与不达标处理。** 数据没有改善趋势时：先复盘归因（区分内容、投放、承接、客户配合四类），再出优化方案；达到约定终止条件就按合同结算终止。**不得用“再做一个月就好了”含糊延期，也不得拿“平台限流”当挡箭牌**（手册 F.5 明确“不要怀疑限流”：权重不影响涨粉，内容才影响）。
13. **客户坚持要效果承诺时的合规回复。** 用 V2-2.1 的标准话术：不能承诺结果（结果取决于客户的产品、价格、交付与配合度）→ 能承诺过程（每月 X 条成片、X 次复盘、完整的选题与脚本交付）→ 三个月后数据没改善可以复盘原因、也可以终止合作。**明确告诉客户这是红线，不能破。** 产出：话术执行记录。
14. **预算远低于产能成本时，用产能倒推。** 先算清这个客户每月实际消耗多少人天，再对比预算；算不平就直说做不到，宁可拒单。不要用“先低价签下来再说”去填产能。产出：接单/拒单结论 + 计算过程。
15. **客户要矩阵时说明缺口。** 知识库里**没有矩阵方法论**（手册只提到官方产品可最多登录 5 个账号、每个账号独立工作区、可给客户开子账号，属工具能力说明）。按 `<skill-directory>/../knowledge/矩阵-待补充.md` 处理：先说清缺口，只给可计算的部分（多账号产能测算、要补几个人、一个人能带几个号），**不输出**账号类型划分、内容差异化策略、账号间导流设计、平台多账号规则判断。产出：缺口说明 + 产能测算。
16. **管产能。** 按“三个月一个周期”规划人数配比与排期（见下节）。产出：产能表 + 排期表。
17. **走标准化路径。** 四阶段：接单赚钱（什么都接，留全部数据记录）→ 筛选行业（只接熟的行业，做行业方案模板）→ 产品化（定档位、定交付物、定价格，不再一客一议）→ 做工具/培训。第 2 阶段是转折点：选题可复用、脚本可模板化、报价可以更高。产出：行业方案模板（可套用 `<skill-directory>/../knowledge/薛辉手册/29-附录E-行业选题地图范本-美食账号.md` 的“视频形式 / 内容主题 / 受众人群”三维拆解方法）。
18. **需要对外讲体系可靠性时正负并列。** 引用前读 `<skill-directory>/../knowledge/薛辉手册/28-附录D-第三方评价-正面与负面并列.md`：正面（MCN 从业者认可其逻辑、学员反馈）与负面（知乎“全是录播、班主任什么都不管”、黑猫投诉“原来说好的包把账号做下来”）**必须一起引**，不加评论性贬损、也不淡化问题，让客户自己判断。产出：对客户的体系说明（正负并列）。

### 产能管理细则

按“三个月一个周期”设计产能规划（【本手册推断·落地建议】）：

| 同时服务客户数 | 建议配置 | 说明 |
|---|---|---|
| 1–2 个 | 个人可承担 | 内容制作 + 运营一人完成 |
| 3–5 个 | 需要 1 名剪辑 | 一人负责选题脚本，剪辑外包 |
| 5 个以上 | 需要团队 | 转 `shortvideo-team` 看岗位配置 |

- **排期方法**：以“周”为最小排期单位，先把每个客户固定的交付节点（成片数、周报、月报、复盘会）铺进日历，再填临时需求；排不进去的临时需求就是**该拒的增量**。
- **超载信号（出现任意两条即应拒单或加人）**：连续两周有交付延期；修改次数持续超合同额度；一个月内出现两次“素材没到位导致停摆”；复盘会被压缩或取消；自己开始用低价换签约。
- **不要超载接单。** 代运营的口碑来自完得成，不是接得多。一个做砸的客户，会带走他圈子里的所有潜在客户。

## 失败与回退

- **客户坚持要效果承诺**：先给 V2-2.1 合规话术（不能承诺结果 → 承诺过程 → 允许复盘与终止）。客户仍不接受，**明确说明这是红线不能破**，礼貌放弃这单。绝不签“保证涨粉”“做不到全额退款”。
- **客户预算远低于产能成本**：用产能倒推说清做不到（列出每月人天与成本，对比预算），宁可拒单。不接亏本单、不用低价填产能。
- **客户要求先做再谈钱 / 拒付预付款**：按合同风险第 8 项处理，不接受“做完再付”。
- **客户要矩阵**：按 `<skill-directory>/../knowledge/矩阵-待补充.md` 说明知识库缺矩阵方法论，只输出产能测算与要补的人力，不编造账号类型划分、内容差异化策略与导流设计。
- **客户问视频号代运营**：⚠️ 视频号不在本手册覆盖范围内。**以下为抖音体系之外的通用实践，非本手册内容，需按视频号实际规则验证**；把抖音的 DOU+ 定向逻辑、5 秒完播率的权重地位、电商罗盘指标直接搬过去是错的，详见 `<skill-directory>/../knowledge/平台差异-抖音与视频号.md`。
- **客户问“能不能帮我把号做起来”**：属于结果性承诺，按红线一节回答，不要含糊应付。
- **客户拿同行“包涨粉”的承诺来压价**：不跟价、不跟承诺，说明越拍胸脯“包做成”的同行越不可靠——他们用承诺换签约，把风险留到三个月后。
- **手册/知识库缺逐字话术**：手册只给结构框架与照读句式，客户沟通话术、直播话术需要自己填，说清“只有结构，逐字内容需要自己写”。
- **涉及具体数值**：价格、粉丝量、流量占比等数据来自特定时点的第三方整理，引用时必须带出处时点与时效警告——`该数值来自特定时点的第三方整理（如约 2022 年的直播流量来源结构、公开渠道的课程价格、2025 年的账号粉丝量），抖音规则与大盘持续变化，请以官方当前数据（如抖音电商罗盘）为准。` 另需知道：手册课程价格（4980/5980/7980 元）是薛辉自身课程产品定价，**与代运营报价无关**。
- **客户要求“必须有依据 / 是薛辉说的”**：本视角全部是【本手册推断·落地建议】，**不是薛辉原话**；引第三方评价时正负并列（`<skill-directory>/../knowledge/薛辉手册/28-附录D-第三方评价-正面与负面并列.md`），不挑一边讲，也不替客户下结论。
- **对话里出现用户自己的效果承诺截图/草稿**：提示风险并帮其改写为过程性表述，不替用户背书。
- **脚本报错**：照脚本报错改正 JSON 字段，**不要绕过脚本自己拼 Office 文件**。
