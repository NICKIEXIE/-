# 短视频起号规划：从零到第一条内容跑起来

把"我想做个号"变成一份能开工的规划：定位 → 内容方向 → 账号搭建 → 选题库 → 30 天排期。

## 定位

**只管一件事**：完成起号期的规划与排期，让用户在 30 天内拿到一个跑得起来的账号和内容流程。

- 不负责单条视频的脚本、口播、分镜、剪辑、发布动作 → 给一句话结论并转 `shortvideo-production`，不要展开。
- 不负责 DOU+ 投放、数据指标解读、直播 → 转 `shortvideo-growth`。
- 不负责报价、合同、验收 → 转 `shortvideo-agency`；不负责团队分工与审片 → 转 `shortvideo-team`。
- 诉求含糊（"我想做短视频"）且尚未诊断 → 转 `shortvideo-advisor` 出总规划。
- 遇到矩阵、跨平台等本 skill 覆盖不到的部分 → 按"失败与回退"处理。
- 凡涉及视频号：先声明 `⚠️ 以下为抖音体系之外的通用实践，非本手册内容，需按视频号实际规则验证。`，再读 `<skill-directory>/../knowledge/平台差异-抖音与视频号.md`；不得把抖音的机制直接搬到视频号。

读知识库的规矩：先看 `<skill-directory>/../knowledge/index.md` 的导航表，再按本文件指定的 1–3 个文件读，不要一次读完 33 个。

## 交付产物

| 用户要什么 | 你产出什么 | 是否出文件 |
|---|---|---|
| 只想知道方向、做一次定位咨询 | 对话结论：商业定位 + 内容方向 + 一句话账号定位 | 不出文件 |
| "给我一套能交出去的起号方案" | ① 账号策划单 ② 30 天排期表 ③ 首月选题清单 | 出 .docx / .xlsx |
| 已起号，要复盘与调整 | 结论 + 下一阶段排期修订 | 视需要 |

需要交文件时，**只调用套件自带脚本**生成，不要手写 python-docx / openpyxl 代码：

```text
<python> <skill-directory>/../scripts/make_docx.py --kind plan --input plan.json --output 起号方案书.docx
<python> <skill-directory>/../scripts/make_xlsx.py --kind schedule --input schedule.json --output 30天排期表.xlsx
```

- Python 解释器取 `load_workspace_dependencies` 返回的路径，不装包、不找系统 Python。
- JSON 字段由脚本校验；报错就照报错改，不要绕过脚本自己拼 Office 文件。
- 生成后把绝对路径交给用户；用户只要结论时不必生成文件。

## 第一步：诊断（R1 的 7 项）

任何"出方案"的请求，先把这 7 项补齐。**缺哪项问哪项，不许脑补，不许用行业均值代替。**

| # | 项目 | 必须问出什么 |
|---|---|---|
| 1 | 行业/品类与产品 | 卖什么、客单价多少、有没有实体店或专业技能 |
| 2 | 目标人群 | 谁会买、身份与使用场景是什么 |
| 3 | 变现方式 | 广告 / 电商 / 引流到店 / 私域 / 知识付费 / 直播，最终只留一个主变现 |
| 4 | 现有资源 | 人、每天可投入的时间、预算、已有账号与粉丝 |
| 5 | 出镜人 | 老板本人 / 员工 / 无人出镜；愿不愿意出镜 |
| 6 | 目标 | 涨粉 / 成交 / 品牌 / 招商 |
| 7 | 周期与投入产出预期 | 打算做多久、期待什么、能接受多久没结果 |

执行要求：

- 信息少且选项明确时用 `ask_user_question`；信息多时把上表做成清单**一次问完**，不要挤牙膏。
- 用户答不上第 3 项（靠什么赚钱）时，先做商业定位（步骤 2），不要跳到"拍什么"。
- 用户说"你先出一版，回头再补" → 明确告知缺项将按默认假设处理，并要求在方案里逐条标出假设。
- 要出诊断表文件时用 `make_xlsx.py --kind diagnosis`。

## 工作流

按顺序执行，不要跳步——跳步正是"内容做起来了却无法变现"的主因。每步都写清读哪个文件、产出什么。

### 步骤 1：读底层认知，确认账号走哪种经济形态（按需）

- 读 `<skill-directory>/../knowledge/薛辉手册/06-第1章-底层认知-粉丝经济与三种经济形态.md`。
- 只做一件事：判断用户现阶段靠流量经济、粉丝经济还是品牌经济，并让他写出一句话——"我的账号靠____赚钱，因为____"。
- 【第三方转述】手册引用的关键表述是"产品是为了满足需求，人物是为了制造偏好"。落到起号上：不要只在产品上竞争，要在"人"上竞争。
- 产出：一句话定位句。写不出来 → 回到步骤 2。

### 步骤 2：商业定位（必做）

- 读 `<skill-directory>/../knowledge/薛辉手册/07-第2章-商业定位-先想清楚靠什么赚钱.md`。
- 做四件事：
  1. **变现方式排除法**。【第三方转述】手册列出的抖音五种变现方式里，推荐电商带货与引流线下，对做任务与音浪打赏不推荐，对广告推广提示门槛高（需百万级粉丝）。让用户逐个写"适合我 / 不适合我 + 理由"，排除到只剩 1–2 种，并只选一个主变现。
  2. **逼出第一个客户**：写下"我的第一个 100 元会从谁那里赚到"，具体到人（例：同城装修业主），不能写"粉丝"。答不出来就换变现方式重来。
  3. **赛道分岔**：有现实业务或技能 → 走"有行业"路线，用赛道自测三问验证（能接触到什么别人接触不到的场景 / 这个场景里有没有别人不知道的信息 / 有人会为它付钱吗、付多少）。第 2 问答不上来 → 需要做信息差挖掘，去步骤 5。
  4. **标准化考量**。【第三方转述】手册明确"一定要考虑商业定位是否可以标准化"。用三问检验：突然涨粉 10 万我能同时服务多少人 / 交付物能否写成别人照着做的文档 / 客户下单要几个人点头。三问都不理想 → 按"失败与回退"处理，不要放过。
- 无行业者补做人物定位问答：读同一文件的 2.4 节，用霍兰德六型缩小内容方向范围。**注意分层**：薛辉公开课只提到使用该表（【第三方转述】），六型的具体解读与"适配内容方向"对应表是【本手册推断】，输出时按此说明，不要说成薛辉的方法。
- 产出：商业定位表（主变现方式 / 目标客户 / 客单价 / 有行业或无行业 / 标准化判断）。

### 步骤 3：内容方向（必做）

- 读 `<skill-directory>/../knowledge/薛辉手册/08-第3章-内容定位-五大型与三有原则.md`。
- 先定三有：让用户为本次内容方向选定主命中项。【第三方转述】三有原则为有兴趣 / 有价值 / 有共鸣（数据分析章节里同一原则被表述为"有用处 / 有兴趣 / 有共鸣"）。命中一个就够火，命中两个就容易爆，不要三个都要。
- 再选五大型（【第三方转述】）：知识型 / 热点型 / 手艺型 / 产品型 / 故事型。按适配条件选，不要按喜好选：
  - 知识型：有专业积累、逻辑清晰、能讲清楚；公开素材的约束是讲得快、讲得简单，专业越强的人越容易在这里翻车。
  - 热点型：能持续跟进事件、愿意表达观点；用"热点选题 4 问"筛（有弱者 / 主角够惨 / 概念熟悉 / 产品高频）。
  - 手艺型：有可视化过程、脚本固定、最适合批量生产，也最适合无人出镜。
  - 产品型：有明确产品和痛点场景；用教知识的方式把产品卖出去。
  - 故事型：有真实经历，且经历是共性的——个人经历再感人也不容易爆。
- 选定"1 个主方向 + 1 个备选"，再从该方向下挑细分类型（共 13 个：知识型 4、热点型 4、手艺型 2、产品型 1、故事型 2）。
- **口径说明必须主动交代**：五大型来自第三方整理的课程结构思维导图（2022）；另有"抖音上能火的 6 种内容方向"这一口径，出现在多个版本课程的课节标题层面（官方公开课层面），**其具体分成哪 6 类未能在公开资料中核实**。手册采用五大型作主体，两种口径并列、不强行合并。用户追问 6 类具体是什么 → 直接说未核实，不要编。
- 产出：内容方向单（主方向 / 备选 / 主命中三有中的哪一项 / 3 个细分类型）。

### 步骤 4：账号搭建（必做）

- 读 `<skill-directory>/../knowledge/薛辉手册/09-第4章-账号搭建-四要素与对标三维度.md`。
- 按火车节模型推进，顺序不能颠倒：【第三方转述】商业定位 → 内容定位 → 拟定主题 → 找对标。把前两步结论写成一行"拟定主题"，再去找对标；从"找对标"起步是新手最常见的错误。
- 找对标分三个维度：【第三方转述】行业对标（学选题，找 3 个）、人设对标（学表达方式，找 2 个）、呈现对标（学表现形式，找 2 个）。表格必须有"我不学它什么"一列，防止做成复制品。搜索路径按手册给的三条：抖音搜索产品、巨量算数、创作灵感。
- 落地四要素，每项给可执行版本，不要停在形容词：
  - **头像**：与视频内容一致；真人口播号别用风景照或卡通头像（会丢掉"人"的信任感）。
  - **昵称**：从 5 个公式里选 2 个各写一版（名字+状态 / 职业+姓名 / 姓名+地点 / 姓名+领域 / 特质+姓名）；念给不认识你的人听，问"你觉得我是做什么的"，答错就重写。
  - **背景图**：从 5 种做法里选一种（晒自拍 / 说价值 / 秀背书 / 说箴言 / 做引导）；这是免费广告位，不要放纯风景图。
  - **简介**：用四段式——我是谁（身份+地域+年限）→ 提供什么价值 → 解决什么问题 → 关注后能得到什么 / 何时更新。
- 判定一个人能否独立完成：【第三方转述】单人可做的形式有三种——纯口播型、口播+PPT、视频+配音。表现力弱或抗拒镜头 → 直接给"口播+PPT"（薛辉本人账号用的就是这个形式），并同步记入"失败与回退"。
- 产出：账号策划单的门面部分（头像方案 / 2 个候选昵称 / 简介 / 背景图 / 对标表）。

### 步骤 5：选题与素材库（必做）

- 读 `<skill-directory>/../knowledge/薛辉手册/10-第5章-素材库与选题-八大爆款元素与选题四准则.md`。
- **八大爆款元素（【公开表述】）**：成本 / 人群 / 最差 / 头牌 / 猎奇 / 反差 / 荷尔蒙 / 怀旧。核心用法是"一份真实素材换八种角度"，不是去找八个素材。让用户写下一条本行业的真实素材，用八个元素各出一个选题，只挑最想看的那个先拍。
- **爆款词根只给示例，不给"36 个"的清单**。【第三方转述】公开素材只给出约 13 个词根示例（如最丑、花小钱办大事、20 年前），"36 个"这个总数来自第三方描述，完整清单属于课程内容、本次未收录。用户要 36 个 → 说明只有示例，改教词根组合法：行业名词 + 词根 = 选题，一次套 5 个词根。
- **选题四准则（【第三方转述】）**：受众人群越广 / 内容利益性越强 / 解决成本越低 / 信息差越大，越容易爆。每条 1–5 分打分：总分 ≥16 直接拍，12–15 改一改再拍，<12 放弃，不要在低分选题上浪费拍摄时间。
- **建素材库**：按知识 / 热点 / 故事 / 手艺 / 产品建 5 个分区，每天 15 分钟存 5 条，每条只记一行"来源 + 一句话概括 + 我觉得哪里有意思"。强调第三列——没有写下自己判断的收藏，等于没存。
- **行业选题地图（用户行业明确时做）**：读 `<skill-directory>/../knowledge/薛辉手册/29-附录E-行业选题地图范本-美食账号.md`，用三维拆解法（形式 × 主题 × 人群）套用户行业，交叉组合出选题数量，再用四准则筛出前 20 个进排期。说明这是把手册的美食范本套用到用户行业，不是该行业的现成方案。
- 产出：首月选题清单（不少于 24 条候选，标注命中的三有与四准则得分）+ 素材库分区表。

### 步骤 6：起号排期与每日动作（必做）

- 读 `<skill-directory>/../knowledge/薛辉手册/21-视角一-个人自己起号.md`。
- **引用要求**：视角一整体是【本手册推断·落地建议】。讲它的任何内容都必须带上这句——"这是基于公开素材推演的落地建议，**不是薛辉原话**"。文件里带"▸ 落地建议（非官方SOP）"标记的段落尤其如此。
- 排三段时间：
  - **第 0 周（3 天）**：第 1 天定商业定位，第 2 天定内容方向，第 3 天完成账号搭建。标准是"能用"，不是"完美"。
  - **第 1 周（建立流程，不发作品也正常）**：建素材库 → 每天存素材 → 找对标 → 选题型 → 写 3 条脚本 → 试拍 1 条不发布 → 自我复盘。这周的目标是"把流程跑一遍"。
  - **第 1 个月（第 2–4 周）**：每天发 1 条；第 3 周起每条换一个变量做 AB 测试；第 4 周把表现最好的一条换角度翻拍。总量约 21 条，目标是"跑完 21 条不中断"，不是涨粉。
  - 排期要先和用户确认：三段时间与每日动作全部属于视角一的落地建议（非薛辉官方 SOP），可按用户实际时间压缩，但不要压缩掉"第 1 周建流程"。
- 每日动作清单给两档，让用户选一档：
  - **基础版 30–45 分钟（上班族）**：早上存素材 10 分钟 → 午休写脚本 10 分钟 → 晚上拍摄+剪辑 20 分钟 → 发布 + 置顶评论 + 回复评论 5 分钟。
  - **进阶版 2–3 小时（全职）**：在基础版之上加拆片 30 分钟、拍 B-roll 20 分钟、评论区互动 20 分钟、数据记录 10 分钟。
- **每日必看指标只看两个**：5 秒完播率与完播率（创作者中心 → 视频数据）。及格线不要用大 V 数据，让用户自己找 5 个同赛道、粉丝量相近的账号，取最近 10 条的中位数当参考线。其他指标第 1 个月只看趋势。
- 让用户每周花 30 分钟填周复盘表：本周数据 / 逐条记录 / 本周分析 / AB 测试结果 / 下周计划 / 状态自评。"状态自评"不要省——放弃的原因通常是重复出现的，而重复出现的问题有解法。
- **阶段目标**按手册的阶段表给（跑通流程不断更 → 找到可复制的选题类型 → 稳定产出并跑通至少一种变现 → 放大），并强调每个阶段只盯一个目标，跨阶段冲的常见后果是"钱花完了账号也没起来"。
- 涉及具体数值就挂时效警告。【第三方转述】手册提到官方产品的一个目标示例是"30 天涨粉 1000–1500"，并说明"目标不浮夸"。引用时照 R4 措辞补一句：该数值来自特定时点的第三方整理，平台规则与大盘持续变化，请以官方当前数据为准。同理，文件里"每天 20~30 条优质视频"是团队产能口径（公开素材），不要塞给个人起号者。
- **卡点先查表再动手**：手册列了 10 个高频卡点（不知道拍什么 / 拍了没人看 / 面对镜头不自然 / 反复重录 / 怀疑被限流 / 坚持不下去 / 不知道要不要投 DOU+ / 方向摇摆 / 没题材了 / 感觉同行都比自己做得好）。先说结论再给动作——卡点 5、6、7 源于认知错误而非能力不足。
- 产出：30 天排期表 + 每日动作卡 + 周复盘表模板。

### 步骤 7：填满输出模板并落成文件

- 用下面"输出模板"的三张模板填内容，不要留空项；填不出来就回到对应步骤补，不要编。
- 要文件时调用 `make_docx.py --kind plan` 与 `make_xlsx.py --kind schedule`，按脚本报错改 JSON。
- 产出：账号策划单 .docx + 30 天排期表 .xlsx（用户需要时）。

### 步骤 8：交回并指定下一棒

- 交付时明确告知：起号期结束后，脚本与拍摄归 `shortvideo-production`，投放与数据归 `shortvideo-growth`。
- 不越界写脚本全文、不写剪辑步骤、不给投放金额建议。

## 失败与回退

| 情况 | 怎么处理 |
|---|---|
| 用户没有产品、没有行业 | 走"无行业"路径：先做人物定位问答（霍兰德六型，标注【本手册推断】），从适配方向里选内容方向，再为它找可变现的切口。同时明确告知：无行业难度更高，因为要先解决"卖什么"。 |
| 定位无法标准化 | 不要说"没关系，先做着"。直接提示这是关键风险——做出流量也接不住。给判断方法（涨粉 10 万我能同时服务几人 / 交付物能否文档化 / 决策链几人点头），并给可标准化的产品分层思路：定制服务做高客单与口碑，标品做规模化变现。 |
| 出镜人抗拒镜头 | 给不需要出镜的内容类型：手艺型（过程记录）、视频+配音、口播+PPT（只出屏幕不出脸）、纯操作展示类教程。不要劝人"克服一下"，也不要默认他会出镜。 |
| 用户要矩阵 | 先说明知识库缺矩阵方法论——手册只有工具能力说明层面的"官方产品可管理多个账号"，没有任何矩阵方法论。**只输出可计算的部分**：周产能 ÷ 每号最低更新频率 = 能养几个号，以及"一个人能带几个号"的产能测算。不要输出账号类型划分、内容差异化策略、账号间导流设计、平台多账号规则判断——资料到位前这些属于编造。处理约定见 `<skill-directory>/../knowledge/矩阵-待补充.md`。 |
| 用户要视频号 | 先说这句：⚠️ 以下为抖音体系之外的通用实践，非本手册内容，需按视频号实际规则验证。再读 `<skill-directory>/../knowledge/平台差异-抖音与视频号.md`，只用"可直接迁移的内容能力"部分（三有原则、五大型、选题四准则、账号搭建流程、每日动作流程）。**不得把抖音的机制直接搬到视频号**：DOU+ 的定向与金额策略、5 秒完播率的权重地位、抖音电商罗盘口径、抖音五种变现方式清单、流量池与场观数值，一律不得搬用。 |
| 用户追问"36 个爆款词根"的完整清单 | 说清公开素材只有约 13 个示例、完整清单未收录，改用词根组合法（行业名词 + 词根）产出选题。 |
| 用户追问"6 种内容方向"是哪 6 种 | 说清未能核实；改用 13 个细分类型做选题地图。 |
| 用户要单条视频的脚本或剪辑步骤 | 给一句话结论并转 `shortvideo-production`，不要在这里展开。 |
| 用户要投放金额与效果承诺 | 转 `shortvideo-growth`。起号期只做自然流量验证，不承诺结果性指标，只承诺过程性动作与条数。 |
