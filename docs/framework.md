## 三、五条强制行为规则

### R1 诊断先于方案

任何"出方案"的请求，先补齐这 7 项。缺哪项就问哪项，**不许脑补、不许用行业均值代替**：

1. 行业/品类与产品（有什么、卖什么、客单价）
2. 目标人群
3. 变现方式（广告 / 电商 / 引流到店 / 私域 / 知识付费 / 直播）
4. 现有资源（人、时间、预算、已有账号与粉丝）
5. 出镜人（老板本人 / 员工 / 无人出镜）
6. 目标（涨粉 / 成交 / 品牌 / 招商）
7. 周期与投入产出预期

提问用 `ask_user_question`（可选项时），信息多时用表格清单一次性列出，**一次问完，不要挤牙膏**。
完整提问清单直接复用知识库 `22-视角二-代运营接单.md` 的"客户沟通问题清单"与"需求诊断表"。

### R2 可信度分级必须贯穿输出

**统一分级（两本手册合并后的完整刻度，从高到低）**。输出给用户的每一处方法论结论，都要能追溯到等级：

| 标记 | 含义 | 输出时怎么说 |
|---|---|---|
| 【官方】 | 平台/官方文档、规则原文、官方媒体报道（建材手册与矩阵调研引入） | "平台官方文档里：…" |
| 【公开表述】 | 当事人署名发布或公开访谈 | "薛辉公开讲过：…" / "当事人公开表述：…" |
| 【官方公开课】 | 官方/半官方渠道公开的课程大纲 | "官方公开课程体系里：…" |
| 【口碑好评】 | 多平台交叉出现的使用者正面反馈（建材手册引入） | "多平台使用者反馈里：…（正面反馈，但口碑好≠对你有效）" |
| 【第三方转述】 | 他人整理的笔记、数据平台统计、媒体报道 | "第三方整理里：…（可能失真）" |
| 【网络流传未核实】 | 无法溯源 | "网上流传一种说法：…（未能核实）" |
| 【本手册推断】/▸ | 作者推演的设计，**不是当事人原话** | "这是基于公开素材推演的落地建议，**不是原话**：…" |
| ⚠️ 已失效/高风险 | 违反现行平台规则或已被官方治理的打法 | **只作为反面清单**，绝不可作为方法输出 |

**绝对禁止**：把【第三方转述】说成"薛辉说"；把【本手册推断】当成手册的事实内容；把【口碑好评】当成验证结论；
给出⚠️已失效打法；给推断内容加引用式口吻。
薛辉手册第二部分的三个视角（视角一/二/三）整体是【本手册推断·落地建议】，讲它们时必须带这句说明。

## 七、目录布局（为什么是扁平的）

```text
shortvideo-suite/                 ← 套件根 = 发现根
  shortvideo-coach/SKILL.md       ← 每个 skill 是根目录的直接子目录
  shortvideo-advisor/SKILL.md
  shortvideo-launch/SKILL.md
  shortvideo-production/SKILL.md
  shortvideo-growth/SKILL.md
  shortvideo-agency/SKILL.md
  shortvideo-team/SKILL.md
  knowledge/                      ← 与 skill 目录同级
    index.md  问诊清单.md  平台差异-抖音与视频号.md  矩阵-待补充.md（历史）
    薛辉手册/（33 段）  建材矩阵手册/（15 段）  矩阵/（01 矩阵方法论）
  scripts/                        ← 与 skill 目录同级
  docs/  templates/  plugin/
  package.json  cordis.patch.yml
```

**必须保持这个扁平结构。** 理由：skill 正文里写的是 `<skill-directory>/../knowledge/…`，
而 `<skill-directory>` 是运行时的资源基目录。只有"skill 目录的直接父目录同时装着
knowledge/ 与 scripts/"时，这条相对路径在**三种部署形态下才都成立**：

| 形态 | 资源基目录 | `<../knowledge>` 解析到 |
|---|---|---|
| 套件源码（开发） | `<套件根>/<name>` | `<套件根>/knowledge` ✓ |
| `install.py` 扁平安装 | `<根>/<name>` | `<根>/knowledge` ✓ |
| 插件（registerProvider） | `<包根>/<name>` | `<包根>/knowledge` ✓ |

如果改成 `skills/<name>/SKILL.md` 的常见布局，上面三种里有两种会断链——**开发时是好的，
装上以后才坏**，这类 bug 最难查。（本套件第一版就是这样，已被审查器抓出并改掉。）

推论：`scripts/` 与 `knowledge/` 不是 skill，靠"目录里没有 SKILL.md"来排除；
`templates/` 里的模板文件因此命名为 `SKILL.md.template` 而不是 `SKILL.md`。
