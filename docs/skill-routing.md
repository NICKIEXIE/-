# skill 路由表（description 逐字定稿）

**每个 skill 的 description 必须逐字写入对应 SKILL.md 的 frontmatter，不得改写、不得加长。**
description 是唯一的路由信号：模型平时只看得到它，超 500 字符会被截断。

写入时必须是**单行**，不要换行。

**边界要点**（改 description 前先读）：

- `shortvideo-advisor` = **学**（想学、想搞懂、不确定方向、要一次性评估）
- `shortvideo-coach` = **做**（要做账号、要一步步带、要长期盯、要文案脚本）
- 两者都会命中"我想做短视频"。判据：用户要**理解**还是**产出**；要产出但没有具体信息 → coach 先问诊。

## `shortvideo-advisor`

```
当用户想做短视频/自媒体但诉求含糊、需要整体规划或学习路径时使用：先诊断行业、资源、变现方式与目标，判定属于个人起号、内容制作、投放增长、代运营接单还是带团队，给出总规划并转入对应能力 skill；也负责讲师模式（按 8 周路径带学、出题与批改）。用户说"我想做短视频""想学短视频运营""帮我规划一下""自媒体怎么做""从哪开始"时使用。
```

## `shortvideo-launch`

```
为抖音/视频号账号做起号规划：商业定位与赛道选择、内容方向（五大型与三有原则）、账号搭建四要素（头像/昵称/背景图/简介）、对标账号三维度、选题与素材库、30 天起号排期与每日动作清单、阶段性目标与卡点解法。用户要求"起号""定位""选赛道""账号搭建""选题""涨粉""排期""每天做什么"，或给出行业要求做账号规划时使用。
```

## `shortvideo-production`

```
单条视频从脚本到发布的制作环节：六类脚本模型与照读句式、口播表现力（真诚/情绪/场景）、分镜与景别构图运镜、剪映核心功能、发布动作与评论区运营。用户问"脚本怎么写""这条视频怎么拍""口播不行/找不到状态""分镜怎么画""剪映怎么剪""标题话题怎么选""这条为什么没播放"时使用。
```

## `shortvideo-agency`

```
把短视频做成代运营生意：先立"不可承诺"的规矩（只承诺过程性指标）、客户沟通与深度诊断问题清单、需求诊断表、交付物清单、分层报价模型、合同风险点、验收标准、多客户产能管理。用户问"代运营怎么接单""怎么报价""签合同注意什么""客户要求保证效果怎么办""交付哪些东西""怎么验收""一个人能接几个客户"时使用。
```

## `shortvideo-coach`

```
当用户要从零做一个账号、要求你一步步带着做、或需要长期陪跑时使用：用拷问式问答（每轮 3–5 问，问清主体/产品/客群/变现/产能/现状/目标/红线）先判定走矩阵还是精品号，边问边落盘《账号档案》，再驱动日常运营——选题、脚本、拍摄清单、发布检查、周复盘与月度诊断，直到账号跑通。用户说"我要做一个账号""帮我从零做起来""接下来每天做什么""这条文案帮我写""盯着我做"时使用。
```

## 校验

写完 6 个 SKILL.md 后：

```powershell
<python> <套件根>/scripts/validate_skills.py <套件根>        # 语法契约
<python> <套件根>/scripts/review_skills.py <套件根>          # 内容契约（引用断链、结构、红线）
```

要求：6 个 skill 全部 `[ OK ]`、0 个错误、无"目录名与 name 不一致"提示。
另需人工核对：description 与上表逐字一致（校验器不比对文案，只校验长度与语法）。
