# 拷问式问诊题库

> **本文件默认服务建材行业**（与 `建材行业短视频矩阵账号运营手册.md` 同源）；非建材行业的替换规则见提问纪律第 8 条。

> **这份文件是什么**：`shortvideo-coach` 的拷问脚本。用户说"我要做一个账号"时，按本文件的 9 轮逐轮提问；
> 9 轮问完才允许出方案。每一轮的"为什么问"和"不同答案的分叉"是强制的——**答案决定方案，不是补充说明**。
>
> **提问纪律（违反任何一条即为问诊失败）**
>
> 1. **每轮 3–5 个问题**，不多不少；问题多就拆到下一轮，不要挤牙膏式一次问一个。
> 2. **一轮一次问完**。用 `ask_user_question`；可选项时给选项，开放题时给填空模板。
> 3. **不许脑补，不许用行业均值代替**用户答案（`framework.md` R1）。用户答"不知道"→ 标记为缺口，继续下一轮，
>    在方案里显式写"此项未知，按 XX 假设推进，需用户确认"，不得静默填默认值。
> 4. **答案必须落盘**：每轮答完立刻按文末"答案落盘格式"写入账号档案；档案里缺少来源字段的答案视为无效。
> 5. **来源必须带等级**。本文件的"来源"列同时给出文件名与可信度标记。三套标记不能混用：
>    - 薛辉手册（`knowledge/薛辉手册/`）：【公开表述】/【官方公开课】/【第三方转述】/【网络流传未核实】/【本手册推断】
>    - 建材手册（`knowledge/建材矩阵手册/01-封面与边界说明.md` 起，共 15 段）：【官方】/【公开表述】/【口碑好评】/【第三方转述】/【网络流传未核实】/【本手册推断】/ ▸ 落地建议
>    - 矩阵文件（`knowledge/矩阵/01-矩阵方法论-建材行业实证.md`）：沿用建材手册分级，另加【口碑好评】
> 6. 讲【本手册推断】类内容时，**必须说"这不是薛辉原话，是基于公开素材推演的落地建议"**（`framework.md` R2）。
> 7. **视频号相关问题一律标 `⚠️ 非本手册内容`**：薛辉手册完全未覆盖视频号（`27-附录C` C.1 缺口、`framework.md` R5）。
>    建材手册第 1.4 节的抖音/视频号对照是【第三方转述】的非官方对照，引用时必须带时效提醒。
> 8. **建材行业专属问题**（B端/C端、1主3辅、门窗/瓷砖等品类、同城半径、工地素材）已在文首、第 1 轮与第 6 轮标注
>    "**建材行业专属，其他行业需替换为对应客群与品类**"；第 3、5、8 轮的 B/C 分线与线索承接口径同属建材版。
>    非建材行业提问时，这些组整体替换，不得原样照问（替代客群请按 `建材手册 1.3` 的"关键内容"一列改写）。
> 9. **凡涉及数值**（56 条/周、28 条/周、日更 3 条上限、B端转化率 3%~10% 等）必须同时给出**来源**与**时效提醒**，
>    因为平台规则与大盘持续变化（`framework.md` R4、`01-矩阵方法论`第五节）。
>
> **9 个维度的顺序**：第 0 轮分叉判定 → 1 主体与产品 → 2 客群与地域 → 3 变现与线索承接 → 4 资源与产能
> → 5 账号现状 → 6 内容资产 → 7 目标与考核 → 8 风险与合规红线。

## 第 0 轮：分叉判定（矩阵 还是 精品号）

这一轮**必须最先问**。先定结构再问细节，否则后面 8 轮的问法完全不同，问错方向等于白问。

### 0.1 先算产能（建材手册 0.2 的产能测算表）

把下面六格念给用户，让他当场填：

| 测算项 | 怎么算 | 用户要回答的原话 |
|---|---|---|
| 每周可拍摄时长 | 出镜人 + 拍摄的总小时数，扣除跑工地、接待客户、发货 | "你每周真正能坐下来拍的时间，有几个小时？" |
| 单次拍摄可产出条数 | 同一场景、同一人、同一天拍完，能覆盖几个选题 | "一次拍完，你能切出几条？" |
| 单条剪辑耗时 | 熟练后用剪映模板剪一条的时间 | "你剪一条要多少分钟？" |
| 每周可剪辑总时长 | **不要算理想值**，算真正坐到电脑前的时间 | "你每周实际能剪几个小时？" |
| 每周发布上限 | （拍摄条数 ≤ 剪辑产能）× 可复用次数 | 由 coach 计算，不要求用户算 |
| 维持日更 8 条需要 | 8 条 × 7 天 = **56 条/周** | 由 coach 计算 |

**来源**：建材手册 `0.2（▸ 落地建议，非官方 SOP）`。其中"单账号日更不宜超过 3 条"来自
蝉妈妈运营问答《刚开始做抖音，抖音一天发几个作品好？》，标 **【第三方转述】**；
公式同时在 `矩阵 01` 第五节"排期与产能模型"（▸ 落地建议）中给出。
**时效提醒**：这些是产能测算口径，不是平台规则；平台规则与大盘持续变化，具体数值以官方当前口径为准。

### 0.2 再对矩阵适用条件 4 条

| # | 适用条件 | 判定方法 |
|---|---|---|
| 1 | 有**明确的多类客群**（建材：B端工程商/经销商 与 C端业主） | 第 2 轮会问到，此处先出结论 |
| 2 | 产能足以让**每个号都保持最低更新频率**（宁可减号，不可断更） | 用 0.1 算出的"每周发布上限"比对 |
| 3 | 有**可复用的拍摄素材**（一次拍摄能供多个号使用） | 第 6 轮会问到，此处先出结论 |
| 4 | 老板/团队愿意接受"**不按单号粉丝考核**" | 第 7 轮会问到，此处先出结论 |

**来源**：`矩阵 01 第一节（▸ 落地建议）`；"宁可减号，不可断更"与"空号断更比不开号更伤"另见建材手册 `0.2（▸ 落地建议）`。

### 0.3 判定规则表

| 命中条件数 / 产能区间 | 判定 | 后续动作 |
|---|---|---|
| 4 条全中 **且** 每周发布上限 ≥ 56 条 | 走**矩阵（1 主 3 辅）** | 按建材手册第 3.6 节套拍法逐条照做；第 4 轮不再问"要不要减号" |
| 4 条全中 **且** 每周发布上限 28–56 条 | 走**矩阵（降配版：主号日更 1 + 辅号隔日更，四号合计日产 4–5 条）** | 执行"降配发布法" |
| 命中 3 条 **或** 产能 < 28 条/周 | **先做 1 个号再扩**（主号 + 工程商号 = 2 个）；剩下两个号留到产能提升后再开 | 第 7 章产能提升后回到本轮复判 |
| 客群单一（只有 B 端或只有 C 端）**或** 无可复用素材 | 走**单号精品号**，不做矩阵 | 按第 6 轮内容资产单线深挖，不做第 5 轮的多号差异化 |
| 用户明确坚持"不按单号粉丝考核"= 否 | 走**单号精品号** | 先做出一个能拿结果的号，再谈矩阵 |

**来源**：命中数与产能的对应关系来自建材手册 `0.2（▸ 落地建议）`；"不该做矩阵的信号：产能只能喂饱 1~2 个号；
客群单一；没有可复用素材"来自 `矩阵 01 第一节（▸ 落地建议）`。**这是推演设计，不是平台规定，需按实际情况调整。**

### 0.4 本轮关键问题清单（4 问）

| # | 问题 | 为什么问（决定什么） | 判定规则 / 不同答案的分叉 | 来源 |
|---|---|---|---|---|
| 0-1 | 你每周真正能坐下来拍几个小时？剪辑又能挤出几个小时？一次拍完大概能切出几条？你剪一条要多少分钟？ | 决定 0.1 产能测算的四个输入，进而决定先开几个号 | 算出每周上限 ≥56 → 四号全开；28–56 → 降配（主号日更 + 辅号隔日更）；<28 → 只开 2 个号 | 建材手册 0.2（▸ 落地建议）、矩阵 01 第五节（▸ 落地建议，含【第三方转述】日更 3 条上限） |
| 0-2 | 你的客户里，是只有一类人（比如只做业主），还是明显分成好几类（比如既有装修公司又有业主）？ | 命中矩阵适用条件 1，决定矩阵还是单号 | 只有一类客群 → 单号精品号；至少两类且内容需求互不兼容 → 具备矩阵前提 | 矩阵 01 第一节（▸ 落地建议）、建材手册 1.3（【公开表述】） |
| 0-3 | 你手上有没有可以反复用的素材（工地/车间/仓库/产品/客户案例），还是每次都要重新从零拍？ | 命中矩阵适用条件 3，决定素材能否供多个号消化 | 有可复用素材 → 可做矩阵；每次从零拍 → 先做 1 个号 | 矩阵 01 第一节（▸ 落地建议）、建材手册 6.2（【公开表述】+ ▸ 本手册推断） |
| 0-4 | **你希望我按矩阵来搭，还是按单号精品号来搭？** 如果你选了矩阵，你能接受"不按单个号的粉丝数考核"吗？ | 直问用户偏好 + 命中适用条件 4，决定考核口径与方案形态 | 接受不按单号粉丝考核 → 可走矩阵；不接受 → 走单号精品号（矩阵考核单位是总线索，不是单号粉丝） | 矩阵 01 第一节与第六节（▸ 落地建议） |

> 若用户回答"不知道能不能接受不按粉丝考核"，先讲矩阵最大的陷阱：**用单号思维看矩阵**
> ——一个小粉丝量但客群精准的工程渠道号，价值远高于泛粉号，考核单位是"总线索"（`矩阵 01 第六节 ▸ 落地建议`）。

## 第 3 轮：变现与线索承接

| # | 问题 | 为什么问（决定什么） | 判定规则 / 不同答案的分叉 | 来源 |
|---|---|---|---|---|

## 停问条件（什么时候算问够了，可以出方案）

**全部满足才停问并出方案；任一条不满足，继续问对应的那一轮：**

1. **9 个维度都有答案**：第 0 轮的分叉结论 + 第 1–8 轮的所有必答问题都有用户明确答复，
   或已显式标记为"用户未知，按 XX 假设推进"。
2. **第 0 轮分叉已经明确**：矩阵 / 降配矩阵 / 先做 1 个号再扩 / 单号精品号，四选一已经落地，
   且用户对"不按单号粉丝考核"给出了明确态度。
3. **产能算术已经闭环**：每周发布上限算出来了，且方案里的发布条数 ≤ 该上限；
   若产能 < 28 条/周，账号数已经按降配规则减到 2 个。
4. **变现路径唯一且能回答"第一个 100 元从谁那里赚"**（`薛辉手册 07-第2章 2.1`，【第三方转述】）。
5. **线索入口与承接人已经确定**：六个入口里至少评论区、私信、主页联系方式、视频结尾口播四项有人负责，
   且首响时长可承诺在 24 小时内。
6. **第 8 轮四条红线全部答"不会/不做"**，或已被当场纠正并写入风险项。
7. **目标与验收口径一致**：考核指标已从"粉丝/播放"改为"有效线索数"，验收方式已改为过程性指标。

**必须停手、不许出方案的情况**（`framework.md` R1 与 `薛辉手册 22-视角二` V2-2.1）：

- 用户要求"包做成""保证涨粉 XX 万""保证月销 XX 万""做不到全额退款"——**不得承诺，不得写进方案**；
- 用户说"我很忙，全交给你了"且不愿出镜——高危信号，先讲清风险再决定是否继续；
- 用户期望"一个月爆"——先做预期管理，未达共识不出方案；
- 第 8 轮任一红线用户坚持要做——**终止问诊，不出方案**。

## 答案落盘格式（供 coach 写进账号档案）

每题一个字段；`qid` 用"轮次-序号"（如 `3-3`）。**档案里缺 `source` 的答案视为无效。**

| 字段名 | 含义 | 取值示例 |
|---|---|---|
| `qid` | 题目编号 | `0-1` / `4-5` |
| `round` | 所属轮次 | `0`–`8` |
| `answer` | 用户原话或结构化答案（**不要改写成抽象字段名**） | `"每周能拍 4 小时，一次拍完能切 10 条，剪一条 25 分钟"` |
| `computed` | coach 由答案算出的值 | `每周发布上限 = 32 条/周` |
| `branch` | 这个答案导致的分叉结论 | `降配矩阵：主号日更 1 + 辅号隔日更` |
| `source` | 依据出处 + 可信度等级 | `建材手册 0.2（▸ 落地建议）` |
| `confidence` | 该来源的可信度等级原文 | `▸ 落地建议` / `【官方】` / `【第三方转述】` / `【本手册推断·落地建议】` |
| `platform` | 适用平台 | `抖音` / `视频号（⚠️ 非本手册内容）` |
| `timeliness` | 时效提醒（涉及数值时必填） | `产能口径非平台规则，具体数值以官方当前口径为准` |
| `industry_scope` | 是否行业专属 | `建材专属` / `通用` |
| `gap` | 用户未答或答不清时记录 | `用户未知：素材可复用次数（待确认）` |

**档案里必须存在的汇总字段**（供第 0 轮分叉与方案生成使用）：

| 汇总字段 | 来源题目 | 说明 |
|---|---|---|
| `account_structure` | 0-1 ~ 0-4 | 矩阵 / 降配矩阵 / 先做 1 个号 / 单号精品号 |
| `weekly_capacity_cap` | 0-1 | 每周发布上限（条/周），由 coach 计算 |
| `bc_split` | 2-1 | B 端与 C 端的占比估计 |
| `geo_radius` | 2-3 | 同城 / 周边区县 / 跨区域 |
| `platforms` | 2-5、5-4 | 抖音 + 视频号（视频号部分必须带 `⚠️ 非本手册内容`） |
| `monetization` | 3-1、3-2 | 唯一变现方式 + 第一个 100 元的来源 |
| `lead_entry_points` | 3-3 | 六个入口中已通的清单 |
| `lead_owner` | 3-4 | 承接人 + 首响承诺时长 |
| `content_form` | 6-3 | 纯口播 / 口播+PPT / 实拍+配音 |
| `kpi` | 7-3 | 有效线索数（**不得为粉丝数/播放量**） |
| `redline_cleared` | 8-1 ~ 8-5 | 红线是否全部通过（`true`/`false`） |
| `gaps` | 全部轮次 | 未答项汇总，随方案一并交用户确认 |
